# 11. [API](../../glossary.md#api) and Data

[Standards index](../README.md) · [简体中文](../../zh-CN/02-development/api-data-standards.md) · [P1](../../glossary.md#priority)


**Scope and owner:** [REST](../../glossary.md#rest), [gRPC](../../glossary.md#grpc) and other [RPC](../../glossary.md#rpc) contracts, databases and [data migrations](../../glossary.md#migration). [Contract](../../glossary.md#contract) owners coordinate consumers; data owners approve [migration](../../glossary.md#migration) and recovery.

## Standards

- **API-01 MUST** define a source of truth: [OpenAPI](../../glossary.md#openapi) for [REST](../../glossary.md#rest), [protobuf](../../glossary.md#protobuf) for [gRPC](../../glossary.md#grpc), or an equivalent [schema](../../glossary.md#schema) for other [RPC](../../glossary.md#rpc) transports. Version it with implementation and examples; validate client generation and compatibility in [CI](../../glossary.md#ci-cd). For [REST](../../glossary.md#rest) prefer resource nouns, consistent casing and [HTTP](../../glossary.md#http) semantics (e.g. `GET /v1/orders/{orderId}`); document filters, allowed sort keys and [bounded pagination](../../glossary.md#pagination) with stable ordering. For [protobuf](../../glossary.md#protobuf), reserve removed field numbers and names.
- **API-02 MUST** document validation, [auth](../../glossary.md#authentication-and-authorization), [rate limits](../../glossary.md#rate-limit), timeouts and stable machine-readable errors. [REST](../../glossary.md#rest) errors use [RFC 9457 Problem Details](../../glossary.md#rfc) or a documented existing envelope. Use 400 for invalid requests, 401 for missing/invalid [authentication](../../glossary.md#authentication-and-authorization), 403 for denied access, 404 for absent or intentionally undisclosed resources, 409 for state conflicts, 429 for [rate limits](../../glossary.md#rate-limit), and 5xx for server faults. For [gRPC](../../glossary.md#grpc) use canonical status codes and safe details. Do not reveal stack traces, secrets or [cross-tenant](../../glossary.md#tenant-isolation) data.
- **API-03 MUST** preserve supported clients for additive changes. Treat removal, changed meaning/defaults, required inputs and incompatible types as breaking; version or stage [migration](../../glossary.md#migration), notify owners and follow [deprecation](../05-maintenance/maintenance-standards.md). Coordinate [schema](../../glossary.md#schema)/package, server, [UI](../../glossary.md#ui), [CLI](../../glossary.md#cli), [SDKs](../../glossary.md#sdk), tests and docs where affected; verify the actual contract version consumed by each changed client.
- **API-04 MUST** design retryable writes for deduplication where duplicate side effects matter. Define [idempotency-key](../../glossary.md#idempotency) scope and expiry, request mismatch behavior and replay result; handle concurrent duplicates atomically. Clients retry only eligible operations within a time budget and honor retry hints.
- **DAT-01 MUST** use consistent [schema](../../glossary.md#schema) naming (default: [snake_case](../../glossary.md#naming-case) for new [SQL](../../glossary.md#sql) [schemas](../../glossary.md#schema)), stable [primary keys](../../glossary.md#primary-key), explicit nullability, constraints and [transaction boundaries](../../glossary.md#transaction). Index from actual query patterns and assess write overhead. Use [UTC](../../glossary.md#utc) for persisted instants, retain business time zone when needed and document public timestamp and [ID](../../glossary.md#id) encodings.
- **DAT-02 MUST** check in and review migrations, validate them on an empty database and a representative upgraded database, and check for model/[schema](../../glossary.md#schema) drift. For [EF Core](../../glossary.md#ef-core) use approved tooling and the project's startup path; review generated [SQL](../../glossary.md#sql) and any manual data-protection adjustments. Check existing rows before adding required fields, unique indexes or [foreign keys](../../glossary.md#primary-key).
- **DAT-03 MUST** define [migration](../../glossary.md#migration) ordering, lock/time budget, batching, resume behavior and safe [rollback](../../glossary.md#rollback)/[roll-forward](../../glossary.md#roll-forward). Use [expand →](../../glossary.md#expand-and-contract) deploy compatible readers/writers → [backfill](../../glossary.md#backfill) and verify → constrain/contract after old clients are retired. Preserve identities and data. Do not put destructive cleanup in the first compatible release.
- **DAT-04 MUST** define backup retention, [RPO](../../glossary.md#rpo) (acceptable data loss) and [RTO](../../glossary.md#rto) (target recovery time); protect backups and rehearse restoration to an isolated environment. Check [schema](../../glossary.md#schema), row/invariant integrity and critical operations after restore. Before irreversible changes verify a recent usable recovery point and decision owner.

## Shared contracts and relational models

- **API-05 MUST** coordinate a shared contract change with its consumers. Agree on the request and response behavior, verify the provider's real mapping and authorize publication through the contract package's release flow. Update consumers to the exact verified package version and test actual calls, permissions and error behavior against a compatible provider. Link contract, provider and consumer changes. Publishing a package and deploying a service have separate verification and delivery records.
- **DAT-05 MUST** represent relational one-to-many relationships with mapped collections and a relationship constraint. Use an owned collection when child records belong to the parent's lifecycle. Use a separate entity relationship when a child has independent identity or lifecycle. After building an affected [EF Core](../../glossary.md#ef-core) service, check for pending model changes against the configured context before completing verification. Generate missing migrations with the project's tooling and review the resulting operations against representative existing data.

Where supported by the project's tooling, run `dotnet ef migrations has-pending-model-changes` with the configured startup project and context. The check detects model changes that still need a migration. Run the upgrade tests separately to verify that existing data survives the migration. See [EF Core migration tooling](https://learn.microsoft.com/en-us/ef/core/managing-schemas/migrations/managing).

## Procedure: add a required column safely

1. Add it nullable or with a safe default. Deploy readers tolerant of the transitional [schema](../../glossary.md#schema) and writers that populate the new value.
2. [Backfill](../../glossary.md#backfill) in resumable batches, preserving [IDs](../../glossary.md#id); compare counts and invariants, measure locks, and check that no rows remain invalid.
3. Enforce the constraint in a separate verified change; remove old data paths only after the agreed compatibility window. Keep the safe recovery point and exercise the restore or [forward fix](../../glossary.md#roll-forward) before a destructive step.

**Evidence:** [Schema](../../glossary.md#schema) diff, [contract tests](../../glossary.md#contract-test) and consumer matrix, generated [migration](../../glossary.md#migration)/[SQL](../../glossary.md#sql), upgrade and restore results, production verification, and the [release record](../04-delivery/release-standards.md).
