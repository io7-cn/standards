# 参考实践

[规范目录](README.md) · [English](../en/reference-patterns.md)

选择适合项目的做法并记录决策。

| 场景 | 推荐做法 |
| --- | --- |
| 一个仓库包含多个组件 | 保持顶层目录和组件所有者清晰，分别记录构建指令与发布触发条件。共享依赖变更时验证受影响的组件。 |
| 已有集成或维护分支 | 记录各分支用途、保护方式、由谁[晋级](../glossary.md#promotion)，以及修复如何进入所有受支持版本。可行时让发布环境独立于分支名称。 |
| 配置跨越多个层次 | 按需同步更新安全默认值、绑定、[部署声明](../glossary.md#manifest)、验证及入门文档。 |
| [共享契约](../glossary.md#contract)发生变更 | 盘点消费方，按需分阶段引入兼容契约，针对消费方实际使用的版本验证。记录[上线](../glossary.md#rollout)顺序及旧版本支持情况。 |
| 构建与部署由不同团队负责 | 交付[不可变制品](../glossary.md#artifact)身份及构建证据。由部署负责人审批[晋级](../glossary.md#promotion)、使[实际状态](../glossary.md#desired-state)与期望一致，并核验实际运行版本。 |
| 迁移或恢复需要演练 | 使用隔离环境和有代表性的脱敏或合成数据。记录已验证版本、耗时、恢复结果及待验证的生产条件。 |
